# Инструкции для работы с проектом

Этот файл действует на весь репозиторий. Он дополняет `CLAUDE.md` конкретными
ориентирами по коду; при изменениях сохраняй согласованность этих инструкций.
Описание возможностей и эксплуатации находится в `README.md`.

## Проект и структура

Telegram-бот для нескольких групп с независимыми настройками, историей,
пересказами и заметками об участниках. Стек: Python 3.12, aiogram 3.x,
aiosqlite, FastAPI, Jinja2 и htmx. LLM вызывается через OpenRouter посредством
`httpx.AsyncClient`. Зависимости закреплены в `requirements.txt`.

- `main.py` — инициализация БД, Telegram polling, веб-сервер, фоновые задачи,
  регистрация команд и корректное завершение работы.
- `bot/handlers/` — команды, регистрация групп, запись сообщений и ответы бота.
  `bot/filters.py` содержит фильтр активных групп `ActiveChat`.
- `core/config.py` — настройки окружения через `pydantic-settings` и `.env`.
- `core/db.py` — схема, SQL-миграции, операции с БД и кэши настроек/активных групп.
- `core/llm.py` — HTTP-клиент, повторы, резервные модели и кэш каталога моделей.
- `core/prompts.py`, `core/moods.py`, `core/profiles.py`, `core/summaries.py` —
  промпты, настроения, заметки и пересказы соответственно.
- `admin/app.py`, `admin/auth.py` — маршруты админки и авторизация.
  `admin/templates/` — страницы и HTML-фрагменты htmx; `admin/static/` — локальные
  стили и htmx, без CDN и отдельной сборки frontend.

## Правила изменений

- Сохраняй асинхронную архитектуру: не добавляй блокирующий ввод-вывод в обработчики
  Telegram, HTTP-маршруты и фоновые циклы. Используй существующие async-клиенты.
- Настройки окружения добавляй через `Settings`; обновляй `.env.example` и при
  необходимости `README.md`. Не записывай реальные токены и пароли в код или логи.
- Пользовательские настройки групп храни в `chat_settings`, получай через
  `get_chat_settings(chat_id)`. Не переноси их в `.env` или глобальную `settings`.
  `GROUP_CHAT_ID` служит только для начального заполнения при пустой таблице групп.
- Сохраняй изоляцию по `chat_id` для истории, профилей, пересказов, настроек и
  переключений настроения. Профиль определяется парой `user_id` и `chat_id`.
  Каталог настроений и кэш каталога моделей общие; текущее настроение — у каждой
  группы своё. `ADMIN_USER_IDS` задаёт общих администраторов бота.
- Новые группы регистрируются неактивными. Обработка сообщений начинается после
  активации в `/chats`; сохраняй проверки `ActiveChat` в обработчиках сообщений.
- Сохраняй порядок роутеров в `bot/handlers/__init__.py`: регистрация групп,
  логирование, команды, общий обработчик чата. Логирование передаёт сообщение
  дальше через `SkipHandler`; новые команды подключай до общего обработчика.
- Используй сырой SQL через `aiosqlite`, параметры запросов и контекстные менеджеры
  `get_db()`, явно фиксируй записи. Не добавляй SQLAlchemy или Alembic.
  Изменения схемы и миграции размещай в `core/db.py`; учитывай существующие базы
  и повторный вызов `init_db()` без потери данных.
- При записи настроек и изменении активности групп сохраняй инвалидацию кэшей.
  Предпочитай существующие функции записи прямому SQL в вызывающем коде.
- Модель передавай в `llm_client.chat()` явно, разрешая её из настроек текущей
  группы для нужной задачи. Сохраняй fallback-цепочку, таймауты, повторы и ограничение
  параллельных запросов. Значение `MODEL` — запасное значение конфигурации,
  а не гарантия доступности модели в OpenRouter.
- Сохраняй отказ от профилирования (`opted_out`), проверки прав для `/profile`
  и `/forgetcontext`, а также подтверждение `/forgetcontext confirm`.
- Защищай новые закрытые маршруты админки через `Depends(require_auth)`.
  Для групповых страниц проверяй существование группы через `_known_chat`.
  Сохраняй экранирование пользовательского текста в HTML и Telegram HTML.
- Для логов используй `logging.getLogger(__name__)`; уровень задаётся конфигурацией.
  Новые зависимости добавляй только с объяснением необходимости.
- Пользовательские сообщения и интерфейс сохраняй на русском. Следуй стилю
  соседнего кода и ограничивай правки задачей. Изменение поведения отражай в README.
- При изменении фоновых задач учитывай отмену и закрытие клиентов в `main.py`.
  Таймаут завершения должен оставаться меньше `stop_grace_period` в Compose.

## Запуск и проверка

Локальная установка и запуск из корня репозитория:

```bash
python3.12 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env
# Заполнить BOT_TOKEN, OPENROUTER_API_KEY и ADMIN_PASSWORD в .env.
.venv/bin/python main.py
```

Не перезаписывай существующий `.env`. Альтернативный запуск —
`docker compose up -d --build`, просмотр логов — `docker compose logs -f`.
Админка слушает `ADMIN_PORT` (по умолчанию 8080); `/health` — простая проверка HTTP,
она не подтверждает работоспособность Telegram или OpenRouter.

Автономные тесты установщика Proxmox: `python3 -m unittest discover -s tests`.
Для shell-скриптов выполняй `bash -n` и, если доступен, `shellcheck`.
Набора тестов логики бота и общей конфигурации линтера пока нет.
Минимальная проверка после правок Python:

```bash
.venv/bin/python -m compileall -q main.py bot core admin
git diff --check
```

Компиляция проверяет только синтаксис. Для изменений логики добавляй или выполняй
целевые проверки затронутого поведения. Используй временную SQLite-базу и подмены
Telegram/OpenRouter для автономных проверок; не запускай `main.py` как тест,
поскольку он подключается к реальным сервисам и запускает фоновые задачи.
`settings = Settings()` создаётся при импорте, поэтому тестовое окружение с
фиктивными обязательными значениями и временным `DB_PATH` задавай до импорта.

Для изменений БД проверяй новую базу, обновление старой схемы и повторную
инициализацию; для групповой логики — независимость двух чатов. Для админки
проверяй авторизацию, полную страницу и затронутые htmx-фрагменты. В итоговом
ответе указывай выполненные проверки и то, что осталось непроверенным.
